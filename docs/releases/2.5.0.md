# 2.5.0 release verification

Date: 2026-09-10. Baseline: repository tag `v2.4.0`; the installed skill matched that snapshot before this update. The reference travel application is read-only input to this release.

## Changes and boundaries

- Added implementation-neutral offline identity and interaction architecture references.
- Reconciled older guidance that made fresh online verification a prerequisite for every personal launch or prescribed collapsed modules for every Tools page.
- Added explicit top-of-page overscroll, compact-header safe-area, short-panel, collection-editing, guest packing and late-request acceptance scenarios.
- Updated full Chinese/English documentation and added one pair of synthetic illustrations. A locally corrupted home image was backed up outside the repository, then regenerated from the existing neutral source.
- The static starter, its service worker, the project generator and the audit engine are unchanged. This package does not implement a member backend or prove a production application's offline authorization.

## Verified locally

- 21 Python tests pass for project generation and public-output auditing.
- 13 Node tests pass for the existing neutral starter's date/storage and service-worker behavior.
- Host skill metadata validator passes.
- Documentation versions/local links and ten PNG files in five language pairs pass validation; all image pairs were visually reviewed.
- The new references were reviewed against guest entry, previously authorized offline restart, session-only expiry, confirmed revocation, logout races, account switching and Tools/My ownership scenarios. This is instruction consistency review, not a newly executed authentication backend test or independent agent evaluation.
- No production records, screenshots, account configuration or deployment identifiers are added to the public package. The publication payload is reviewed separately from the private reference application.

## Reproduce

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.cjs
sh scripts/render_readme_screenshots.sh
python3 scripts/check_docs.py
```

Use Python 3.10+, Node.js, Playwright and Chrome/Chromium as described in [image provenance](../SCREENSHOTS.md). The skill host's metadata validator is separate and requires PyYAML. The renderer opens an isolated profile and blocks HTTP assets; this tests the documentation, not a deployed website.

A generated starter intentionally retains final-itinerary placeholders; its release audit must report them until the real guide is populated. Passing these checks does not establish physical iPhone bounce, installed-PWA storage, system printing, real server authorization or multi-device synchronization.

## Package and publication contract

1. Inspect the staged diff, text and all binary assets; preserve existing public repository identity and visibility.
2. Commit and create annotated tag `v2.5.0`. Push the commit and tag atomically to the existing repository.
3. Export that exact tag with `git archive --format=zip --prefix=travel-guide-pwa-builder/`. Keep ZIPs and local receipts outside the repository.
4. Publish the ZIP and `SHA256SUMS` with the GitHub Release. Download the published assets again and compare the checksum and archive contents with the tagged files.
5. Before installing, recheck local changes and back up the installed skill. Install only the verified release snapshot and compare all file hashes; do not alter unrelated skills.

The [GitHub Release](https://github.com/pengguin/travel-guide-pwa-builder/releases/tag/v2.5.0) is the publication receipt. Local build/package success alone does not prove GitHub publication. This release does not modify or republish the reference travel Site.
