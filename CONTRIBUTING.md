# Contributing

Use a separate working copy and preserve the existing project/starter boundary. Keep changes scoped to demonstrated failures or useful reusable decisions; do not paste a traveler's live application or data into this repository.

Before submitting:

1. Run the Python and Node checks documented in the README.
2. Add a synthetic regression for changed executable behavior; do not test only wording.
3. Keep Chinese and English user documentation aligned. Label illustrations as demonstrations, record provenance and inspect regenerated PNGs.
4. Review the complete diff, including image contents and metadata. Do not include credentials, user screenshots, databases, personal bookings or build caches.
5. Update CHANGELOG and the SKILL version when preparing a release. Preserve earlier version history.

A failing check is a result to investigate, not something to suppress. Static audits and VM tests do not prove browser, permission or physical-device acceptance.
